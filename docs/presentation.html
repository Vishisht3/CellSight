The Problem & What CellSight Solves

1.1   Industrial EV adoption is stalled by lack of asset intelligence. India registered 2 million EVs in FY2025, yet industrial segments (freight, mining, logistics, construction) remain below 2.5% penetration (SIAM FY2025). The barrier is not financial - FAME-II has disbursed over Rs 10,000 crore. The barrier is operational: industrial fleet operators lack the asset intelligence tools to manage EV procurement, battery lifecycle, and maintenance with the rigour they apply to conventional equipment.

1.2   EV manufacturers have no supply chain visibility. Battery materials pass through 3+ supplier tiers with no unified risk view. When field packs degrade faster than expected, there is no mechanism to trace back to the originating cell batch or raw material supplier. For India to meet its 30% EV penetration target by 2030, it needs an AI layer that addresses both the industrial adoption gap and the manufacturing supply chain gap simultaneously.

1.3   The gap nobody fills. Field performance data sits with fleet operators. Supply chain data sits with manufacturers. The correlation that would improve both sides is never made. CellSight makes that connection automatically � the only platform that links real-world battery degradation back to the specific cell batch and supplier that caused it.

How the AI Works - OLS Regression & RUL Prediction

5.1   The State of Health on every asset is computed by a bespoke Ordinary Least Squares linear regression implemented entirely in TypeScript - no external ML libraries.

Feature Vector - 7 dimensions
1 (bias term) totalCycles avgVoltage avgTemperature avgStateOfCharge voltageStdDev tempStdDev
100-point sliding window, 50-point stride. Falls back to physics formula if <10 training samples.
Training & RUL Prediction
// Normal equation: β = (XᵀX)⁻¹ Xᵀy // Gauss-Jordan inversion // 80/20 train/test + RMSE // Remaining Useful Life: RUL = (SoH − 80%) ÷ deg/day // From SoH history slope

5.2   The Predictive Maintenance engine runs four automated checks per asset every 5 minutes:

CheckAlgorithmWARNING whenCRITICAL when
Thermal EventLast 10 readings vs limitsTemp > 45°C or < −10°CTemp > 55°C or < −20°C
SoH DegradationcurrentSoH vs thresholdsSoH < 85%SoH < 80%
RUL ThresholdLinear extrapolationRUL ≤ 30 daysRUL ≤ 7 days
Charge PatternLast 100 SoC readingsAvg SoC min < 20% or max > 80%N/A - INFO only
Why no external ML library? The entire OLS pipeline - feature extraction, XᵀX matrix multiplication, Gauss-Jordan inversion, train/test split, RMSE - is ~150 lines of pure TypeScript. This avoids native binary dependencies, keeps the Railway Docker image small, and makes the model fully inspectable without a Python environment.

8.2   Formula:  z = (supplierAvgDegRate − μ) / σ.   Any z > 2.0 (≈ 95th percentile) triggers a FIELD_TO_SOURCE_CORRELATION alert visible to both the fleet manager and supply chain manager simultaneously.

Why this is the core differentiator: CellSight is the only platform that automatically links real-world field degradation back to the specific cell batch and raw material supplier that caused it. When the alert fires, both teams see it at the same time. Z-score is self-calibrating - the threshold adjusts as the fleet grows. No manual tuning required.

9.2   The left border colour gives instant visual severity before reading any text - red for CRITICAL, amber for WARNING. Each alert has contextual links to the affected asset or supplier.

Outbox Pattern - guaranteed delivery:
1. AlertService writes the alert and an outbox_events row in a single atomic transaction - no dual-write inconsistency possible.
2. OutboxPublisher polls unpublished rows every second and pushes to SSE clients.
3. On reconnect, the browser sends a Last-Event-ID header. Server replays all missed events since that ID - no alert is ever lost during a network drop.
