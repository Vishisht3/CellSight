The Problem & What CellSight Solves

1.1   Industrial EV fleets have no Asset Performance Management tooling for their batteries. Fleet managers cannot see degradation rates, thermal risk, or replacement timing — leading to unplanned downtime and accelerated wear from suboptimal charging.

🚛 Fleet Operators — No Battery APM

EV batteries have no equivalent of the APM tools industrial machinery has enjoyed for decades. Managers are flying blind on degradation, thermal risk, and replacement timing.

🏭 Manufacturers — Supply Chain Opacity

Battery materials pass through 3+ supplier tiers with no unified risk view. When field packs degrade faster than expected, there is no way to trace back to the originating cell batch.

1.2   CellSight bridges this gap with three AI agents running on a shared platform — an APM Agent for fleet operators, a Supply Chain Agent for manufacturers, and a Correlation Agent that statistically links field degradation back to the batch and supplier that caused it.

🤖 APM Agent

OLS regression SoH · RUL prediction · Thermal detection · Charge pattern analysis · Predictive maintenance queue

🤖 Supply Chain Agent

4-dimension risk scoring · 3-tier material traceability · Certification compliance · Full chain in <3 s

🔗 Correlation Agent

Z-score outlier detection (z>2.0) · Links batch degradation to suppliers · Cross-team alert visibility

How the AI Works — OLS Regression & RUL Prediction

5.1   The State of Health is computed by a bespoke Ordinary Least Squares linear regression implemented entirely in TypeScript — no external ML libraries.

OLS Regression Model
Input Features (7-dim)
1 (bias)
totalCycles
avgVoltage
avgTemperature
avgStateOfCharge
voltageStdDev
tempStdDev
Training & Inference
Normal equation: β = (XᵀX)⁻¹ Xᵀy
Matrix inversion: Gauss-Jordan elimination
80 / 20 train / test split
RMSE logged at startup
Sliding 100-point windows, 50-point stride
Fallback: physics rule-based formula if <10 training samples or singular matrix
Physics fallback formula:
SoH = 100 − (cycles × 0.05) − voltageFade − tempStress
where voltageFade = max(0, (400V − avgV) / 400) × 10, tempStress = max(0, (avgTemp − 35°C) × 0.2)

5.2   Remaining Useful Life (RUL) is predicted by linear extrapolation from the SoH history slope:

RUL (days) = (currentSoH − 80%) ÷ degradationRatePerDay
Degradation rate = (oldest SoH − newest SoH) ÷ elapsed days. Confidence scales linearly from 0 → 1 as telemetry accumulates (target: 200+ points).

5.3   The Predictive Maintenance engine runs four checks per asset every 5 minutes:

CheckAlgorithmAlert triggered when
Thermal EventLast 10 telemetry readings vs ±10°C limitsTemp < −10°C or > 45°C
SoH DegradationCompare currentSoH to config thresholds< 85% → WARNING, < 80% → CRITICAL
RUL ThresholdLinear RUL extrapolation≤ 30 days WARNING, ≤ 7 days CRITICAL
Charge PatternLast 100 SoC readings, avg min/maxAvg SoC min < 20% or max > 80%
Why no external ML library? The entire regression pipeline — feature extraction, matrix multiplication, Gauss-Jordan inversion, train/test split, RMSE evaluation — is implemented in ~150 lines of pure TypeScript. This avoids large native dependencies on Railway and keeps the Docker image small.

Field-to-Source Correlation — Z-Score Outlier Detection

8.1   Navigate to Correlation in the sidebar and click "Run Analysis". The Correlation Agent computes the average degradation rate of all assets linked to each supplier, then uses z-score statistics to flag outliers.

8.2   The z-score formula is: z = (supplierAvgDegRate − μ) / σ. Any supplier with z > 2.0 (≈ 95th percentile) is flagged as a statistical outlier and a FIELD_TO_SOURCE_CORRELATION alert is raised — visible to both fleet and supply chain managers simultaneously.

Why z-score instead of a fixed 20% threshold? A fixed threshold treats a 21% deviation the same whether the fleet has 3 assets or 300. Z-score is self-calibrating — as the fleet grows and the population distribution changes, the threshold adjusts automatically. No tuning required.

9.2   The left border colour gives instant visual severity — red for CRITICAL, amber for WARNING. Alerts can be Acknowledged (taking ownership) or Resolved (marking fixed) in-place, without leaving the feed.

Outbox Pattern — how alerts reach your browser in real time:
Step 1. AlertService writes the alert record and an outbox_events row in a single atomic database transaction — no dual-write inconsistency possible.
Step 2. OutboxPublisher polls unpublished outbox rows every second and pushes them to SSE (Server-Sent Events) clients.
Step 3. On reconnect, the browser sends a Last-Event-ID header. The server replays all missed events since that ID — no alert is ever lost during network drops.
