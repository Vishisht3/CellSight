The Problem

Industrial EV fleets and battery supply chains operate in silos — with no shared intelligence layer between them
2
🚛 Fleet Operators — No Battery APM

Industrial machinery has decades of Asset Performance Management tooling. EV batteries have none. Fleet managers cannot see real-time degradation rates, thermal risk, or replacement timing — leading to unplanned downtime and accelerated wear from suboptimal charging.

🏭 EV Manufacturers — Supply Chain Opacity

Battery materials traverse 3+ supplier tiers with no unified risk view. Concentration, geopolitical, quality, and compliance risks are siloed. When field packs degrade faster than expected, there is no mechanism to trace back to the originating cell batch or material supplier.

🔗 The Gap Nobody Fills

Field performance data sits with fleet operators. Supply chain data sits with manufacturers. The correlation that would improve both sides — linking real-world battery degradation back to the specific cell batch and raw material supplier that caused it — is never made. CellSight makes that connection.

How the AI Works — OLS Regression & RUL Prediction

All algorithms implemented in pure TypeScript · No external ML libraries · Gauss-Jordan normal equations · 80/20 train/test split
5

State of Health — OLS Linear Regression

// Feature vector per 100-point telemetry window x = [1, totalCycles, avgVoltage, avgTemperature, avgSoC, voltStdDev, tempStdDev] // Normal equation: β = (XᵀX)⁻¹ Xᵀy // Matrix inversion via Gauss-Jordan elimination β = fitOLS(X_train, y_train) // Physics fallback if <10 training samples: SoH = 100 - (cycles × 0.05) - voltageFade - tempStress
Training target is the physics formula applied to sliding windows. Model is trained on every startup, with 80/20 train/test split and RMSE logged. Falls back to the physics formula if the matrix is singular or data is insufficient.

Remaining Useful Life Prediction

// From SoH history slope: degRate = (oldest_SoH - newest_SoH) / days_elapsed // Days until SoH hits 80% (critical floor): RUL_days = (currentSoH - 80%) / degRate // Confidence scales with data volume: confidence = min(1.0, readings / 200)
Linear extrapolation from SoH history. Confidence increases as more telemetry accumulates. RUL ≤ 30 days triggers a WARNING alert; ≤ 7 days triggers CRITICAL — as seen with Forklift-FL05.

Four Automated Maintenance Checks (run every 5 minutes per asset)

CheckAlgorithmWARNING triggered whenCRITICAL triggered when
Thermal EventLast 10 telemetry readings vs safe limitsTemp > 45°C or < −10°CTemp > 55°C or < −20°C
SoH DegradationcurrentSoH vs configured thresholdsSoH < 85%SoH < 80%

Why no external ML library? The entire OLS pipeline — feature extraction, XᵀX matrix multiplication, Gauss-Jordan inversion, train/test split, RMSE evaluation — is ~150 lines of pure TypeScript. This avoids native binary dependencies, keeps the Railway Docker image small, and makes the model fully inspectable without a Python environment.

Z-Score Formula

z = (supplierAvgDegRate − μ) / σ // μ and σ computed across all suppliers // with confidence ≥ 0.5 (≥ 5 linked assets) // Threshold: z > 2.0 ≈ 95th percentile // Self-calibrates as fleet grows — no manual tuning

Red bars are statistical outliers — their assets degrade significantly faster than the fleet population. CobaltMines z = 2.84 means its linked assets degrade faster than 99.8% of the fleet.

Why this is the core differentiator: This is the only platform that automatically links real-world field degradation rates back to the specific cell batch and raw material supplier that caused it.

Outbox Pattern — Guaranteed Delivery

1
AlertService writes the alert record and an outbox_events row in a single atomic database transaction — no dual-write inconsistency possible.
2
OutboxPublisher polls unpublished outbox rows every second and pushes them to all connected SSE clients.
3
On reconnect, the browser sends a Last-Event-ID header. The server replays all missed events since that ID — no alert is lost during network drops.
